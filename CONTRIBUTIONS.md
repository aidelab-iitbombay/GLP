# Contributing to PyGuLP

Thank you for your interest in PyGuLP. Contributions that improve the package, documentation, examples, testing, or support for goal-programming applications are welcome.

## Reporting bugs

If you encounter unexpected behaviour or an error, please open an issue in the GitHub repository.

When reporting a bug, please include, where possible:

- a brief description of the problem;
- steps or a minimal example that reproduces the issue;

## Requesting features

Feature requests may be submitted through GitHub Issues. Please describe the proposed functionality and, where relevant, the type of goal-programming problem or application it is intended to support.

Suggestions for additional goal-programming formulations, modelling utilities, documentation, and worked examples are particularly welcome.

## Contributing code

Code contributions may be submitted through pull requests.

Before submitting a pull request:

1. Fork the repository and create a branch for the proposed change.
2. Ensure that the existing tests pass.
3. Add or update tests where the contribution changes package behaviour.
4. Update relevant documentation or examples where required.
5. Provide a brief description of the change in the pull request.


## Documentation and examples

Contributions that improve documentation or provide additional worked examples are welcome. Examples should, where possible, be self-contained and clearly describe the goals, constraints, inputs, and expected outputs.

## Support

Questions about using PyGuLP, bug reports, and feature requests should be submitted through the GitHub repository's issue tracker.
